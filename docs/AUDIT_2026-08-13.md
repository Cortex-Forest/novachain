# Nova 链 全量审核报告（2026-08-13）

> 范围：后端 `novachain`（节点/共识/经济/存储/算力/SocialFi/聊天/P2P/RPC）+ 前端 `novachain-web`（apps-common.js 与全部页面）。
> 基线：后端 165 项测试全绿；前端在节点模式与演示模式下均可运行。

## 一、架构现状（已核实）

- 交易模型：`Tx`（Ed25519/Dilithium5 签名，`sender==receiver` 特殊交易承载 JSON `data`）。
- 共识：`checkpoint`（默认）与 `pos`（质押加权出块 + 惩罚）双模式；区块只含 txid，状态靠全量快照同步。
- 经济：固定总量 8100 万，出块/部署/推荐/调用奖励 + 生态基金 + 社区空投；存储/算力奖励由生态基金支付。
- 存储网络：注册/固定/认领/哈希链证明/托管订单，`nova:storage:*` 经 `/api/op` 或专用 RPC。
- 算力市场：发布/接受/提交/结算，`nova:compute:*`，双节点同哈希即结算。
- SocialFi：10 类 27 个操作码，前后端操作码集合一致；声誉实时计算；推荐引擎输出算力任务规格。
- 聊天：E2E 加密信箱（节点只存密文），X25519+HKDF+AES-GCM，签名校验完整。
- 前端：`detectMode()` 探测节点（同源 → 127.0.0.1:8080 → localhost:8080），失败降级 localStorage 演示模式；CORS 已放开。

## 二、问题清单

### P0（必须修复，涉及安全或核心协调）
| # | 位置 | 问题 | 影响 |
|---|------|------|------|
| 1 | `nova_node.py::rpc_deploy` | `creator` 字段无签名校验，任意人可传任意地址领取部署奖励（`deploy_reward`，5 NOVA/次，50k 次减半） | 可无成本掏空生态基金 |
| 2 | `network/p2p.py` | `_listen`/`_handle_connection` 每次仅读 16KB 并整体 `json.loads`；`state_snapshot`/大区块消息必被截断 | 状态快照同步、大消息传播在多节点+大数据量下失效 |
| 3 | `core/vm.py` + `nexlang_compiler.py` | VM 为占位实现（固定返回字符串）；编译器 `*`/`/`/`-` 复用 opcode 0x03、无 `+`、无分支/循环 | 合约功能实际不可用，与 README 宣传不符 |

### P1（高风险，需加固）
| # | 位置 | 问题 | 影响 |
|---|------|------|------|
| 4 | `core/compute.py::submit/_complete` | 无 `status` 前置守卫；`expire()` 在 apply 阶段先退款再结算；同区块批量路径存在“先退款后发赏金”的竞态窗口 | 潜在凭空增发/重复结算 |
| 5 | `core/storage_network.py::proof/claim/pin` | 模块内无守卫（依赖 node 层校验）；`proof` 直接索引 `storage_seals[key]`，越界会抛 KeyError | 健壮性差，异常路径难排查 |
| 6 | `nova_node.py::rpc_chat_ack` | 无鉴权，任何地址可删除任意信箱消息 | 数据破坏 |
| 7 | `nova_node.py::rpc_deploy` | system tx（`0x0000`）无签名、无内容校验即上链 | 垃圾合约上链 + 与 #1 叠加 |
| 8 | `network/security.py` | `checkin_history`/`request_log` 无上限裁剪；`check_ip_limit` 用 `startswith(role)` 前缀匹配 | 长期运行内存膨胀；防作弊判定可能误伤 |
| 9 | `nova_node.py::_run_daily_maintenance` | 矿工在线时长按“每日维护+86400”累计，节点离线也计入 | 与实际在线时长不符，影响 9 个月在线奖励判定 |

### P2（优化与一致性）
| # | 位置 | 问题 |
|---|------|------|
| 10 | `core/storage.py::from_dict` | 存在重复恢复代码块（fan_tokens 等重复两次） |
| 11 | `nova_node.py` 多个 RPC | 地址格式、金额、错误码不统一（400 文案混杂） |
| 12 | `core/economy.py::block_reward` | 减半用墙钟而非高度，节点时钟偏差影响奖励 |
| 13 | `network/p2p.py::_create_client_ssl_context` | TLS 客户端 `CERT_NONE`（自签名，生产需固定证书） |
| 14 | 前端 `apps-common.js` | 演示模式缺 `nova:compute:*`/`nova:storage:*` 模拟（socialfi.html 一键发布算力任务在演示模式无反馈） |
| 15 | 前端 | 存储网络无页面；算力市场仅“一键发布”，无任务列表/接受/提交 |
| 16 | `wallet.html` vs `apps-common.js` | Ed25519/HKDF/X25519 重复实现，易漂移 |
| 17 | `nova_node.py::save_state` | `_autosave_loop` 与 `on_cleanup` 可能并发写（os.replace 原子，风险低） |
| 18 | README | 合约 VM、演示模式说明与实际不符，需同步更新 |

## 四、修复路线（对应执行计划第 2、3 阶段）

1. **P0 优先**：#1 部署奖励加签名校验（`creator` 必须签名）；#2 P2P 消息改为长度前缀分帧 + 大消息分块；#3 VM/编译器落地最小可用执行器（或明确标注试验性并禁用奖励）。
2. **P1**：#4 compute 结算加 `status` 守卫与应用期复验；#5 storage_network 模块内加守卫与友好错误；#6 chat ack 加签名或限制为收件人本人；#7 deploy 校验内容与奖励条件；#8 加内存裁剪；#9 改为真实在线统计。
3. **P2**：去重 `from_dict`；统一 RPC 校验与错误码；前端补齐存储/算力页面与演示模拟；统一钱包密码学；文档同步。
4. **端到端验证**：3 节点 + 前端全链路走查；演示模式与节点模式行为对齐；全量回归。
